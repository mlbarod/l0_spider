# 전문 검수 에이전트 역할 경계

## 경계의 목적

같은 현상을 여러 관점에서 볼 수 있지만 각 에이전트는 자신의 증거와 책임만 보고한다. 다른 에이전트의 보고서를 수정하지 않으며, 연관성이 있으면 `연관 에이전트`와 `연관 사유`를 기록한다.

## 책임 구분

| 구분 | Browser QA Agent | Code Audit Agent | Performance Agent |
|---|---|---|---|
| 핵심 질문 | 사용자가 문제없이 사용할 수 있는가 | 잘못된 결과나 숨은 장애를 일으킬 코드가 있는가 | 어디가 느리고 규모가 커져도 견디는가 |
| 주요 증거 | 사용자 재현, 화면, console/page/network | 코드 경로, 계약, 상태·비동기 로직, 테스트 | 반복 측정, network, trace, profile |
| 주요 책임 | 화면 상태, 흐름, 안내, 조작성, 접근성 | 데이터 정합성, 타입·스키마, 캐시·상태, 오류 처리 | 시간, 호출·payload, 렌더링, 번들, 메모리, 확장성 |
| 제외 | 전체 정적 감사, 성능·아키텍처 분석 | 디자인·일반 UX, Lighthouse·성능 튜닝 | 일반 기능·예외 감사, 비즈니스 정확성 판정 |
| 보고서 코드 | `BQA` | `CA` | `PERF` |

## Browser QA Agent

사용자가 눈으로 보고 조작할 수 있고 브라우저에서 재현 가능한 문제를 담당한다. 로딩·빈·부분·실패 상태, 사용자 안내, 화면 깨짐, 키보드 조작, 빠른 조작, console 및 network 오류의 사용자 영향을 기록한다.

코드 전체 구조, query cache 설계, 번들·렌더링 최적화는 분석하지 않는다.

## Code Audit Agent

코드 내부의 잠재 결함, 데이터 정합성, 프런트엔드 관찰 API 계약, 타입, 날짜·숫자 변환, 비동기 응답 순서, React Query, 오류 처리, 메모리 누수 가능성, 테스트 누락을 담당한다.

픽셀·디자인 평가, 사용자 경험 일반론, Lighthouse 점수, 성능 튜닝은 수행하지 않는다.

## Performance Agent

시간, 횟수, 크기, 렌더링, 메모리처럼 측정 가능한 병목과 `single`·`normal`·`large` 증가율을 담당한다. 프런트엔드 제안과 백엔드 API 제안을 분리한다.

일반 기능 오류, 디자인, 예외 처리 전반, 비즈니스 규칙 정확성은 판정하지 않으며 측정 근거 없는 리팩터링을 제안하지 않는다.

## 중복 현상 기록 예

빠른 필터 변경 뒤 이전 데이터가 표시되고 요청도 중복되었다면 다음처럼 분리한다.

- Browser QA: 사용자의 조작 순서, 화면에 보인 이전 값, 재현 횟수와 화면 영향을 기록한다.
- Code Audit: 요청 취소, request identity, query key, out-of-order response 처리의 코드 근거를 기록한다.
- Performance: 필터 변경당 호출 횟수, 중복 요청의 전송량과 대기시간을 측정한다.

각 보고서에는 담당 가능성이 있는 다른 역할을 다음 형식으로 연결한다.

```text
연관 에이전트: Code Audit Agent
연관 사유: 비동기 응답 순서 처리 로직 검토 필요
```

## 공통 금지선

세 에이전트 모두 소스·테스트·설정·의존성을 수정하지 않는다. 확인과 측정 결과를 근거로 수정 방향을 제안할 수 있으나 직접 구현하지 않는다. 데이터 불일치와 판단 불가능 상태를 정상으로 처리하지 않는다.
