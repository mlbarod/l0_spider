# VOE 게시판

메인 Apps의 기존 FDC Hard Limit 추천 자리를 `VOE 게시판`으로 교체한다. 카드 설명과 게시판 헤더 아래 문구는 `원하는 기능을 요청하거나 문의 사항을 등록합니다`이다. 경로는 `/voe`이며 기존 `/hard-limit` 접근은 `/voe`로 이동한다.

Quality-Hub 로컬 저장소의 `prototype/src/qna/QnaApp.jsx`, 서식 편집기와 CSS를 기준으로 목록/상세/작성 화면을 이식했다. 상태 필터, 표·이미지·글씨 크기 편집, 질문/답변 수정, 최종 답변, 알림, 삭제 복구, 변경 이력을 제공한다. 게시판 내부 알림과 새 질문·답변 등록 시 자동 메일 발송을 제공한다.

## 자동 메일

- 질문 등록: 접근 권한 저장소에 현재 등록된 모든 마스터 Knox ID로 발송한다.
- 답변 등록: 모든 마스터와 질문 작성자에게 발송한다. 같은 ID는 한 번만 포함하며, 작성자가 수신 대상이면 본인도 받는다.
- 수정·삭제·복구·상태 변경·최종 답변 지정에는 메일을 보내지 않는다.
- 질문 등록 메일 제목은 `[SPIDER VOE] <카테고리>-<게시글 제목>`, 답변 등록 메일 제목은 `[SPIDER VOE] 답변: <카테고리>-<게시글 제목>`이다.
- 본문은 Quality-Hub의 VOE 메일 양식과 동일한 서식으로 작성자, 구분(카테고리), 게시글 링크, 질문 본문을 표시한다. 답변 등록 시 구분선 아래에 새 답변만 추가한다. Spider에서 사용하지 않는 라인 항목은 생략한다. 표·글씨 크기 등은 유지하고 이미지는 `[이미지: 게시글에서 확인]`으로 대체한다.

Chart Mailing과 같은 `KNOX_MAIL_ENABLED`, `KNOX_MAIL_TOKEN`, `KNOX_MAIL_SYSTEM_ID`, `KNOX_MAIL_TIMEOUT_MS` 및 Knox API를 사용한다. 발신자와 API `userId`는 로그인한 작성자의 Knox ID이며 수신 주소는 `<knox_id>@samsung.com`이다. 링크 주소는 기존 `SSO_REDIRECT_URI`의 서비스 주소에 `/voe?questionId=<번호>`를 붙여 생성한다. 별도 메일 설정이나 DB 테이블 추가는 필요 없다.

DB 저장과 성공 응답 후 발송한다. 발송 비활성화·설정 오류·API 실패 시에도 저장된 글은 유지한다. `[voe-mail]` 로그로 결과를 확인하며, 토큰·수신 주소·본문·원격 응답 원문은 기록하지 않는다. HTTP 접수는 실제 수신 성공을 보장하지 않는다. 중복 발송 방지를 위해 자동 재시도하지 않으며, 별도의 영속 발송 대기열은 없으므로 저장 후 발송 전에 서버가 종료되면 메일이 누락될 수 있다.

## 권한과 저장

기존 Spider SSO와 접근 권한을 사용한다. 작성자는 자신의 질문/답변을 수정할 수 있으며 답변이 없는 질문만 삭제할 수 있다. 마스터는 모든 글 관리, 상태 변경, 최종 답변 지정, 삭제 복구와 변경 이력 조회가 가능하다. 클라이언트가 보낸 사용자 ID·권한을 신뢰하지 않는다. 개발 서버에서도 실제 쓰기에 SSO가 필요하다.

- `spider_voe_posts`: 질문, 답변, 서식/본문 이미지, 삭제 상태를 JSON 문서로 저장. 목록용 요약은 같은 행에 따로 저장하여 이미지 본문을 목록에 보내지 않는다.
- `spider_voe_events`: 변경 이력과 질문 작성자에게 보내는 답변/상태 알림, 읽음 상태를 함께 저장. 별도 사용자·첨부·알림 테이블은 만들지 않는다.

게시글 행을 `FOR UPDATE`로 잠근 뒤 변경 내용과 이력을 같은 트랜잭션으로 저장한다. 본문은 서버에서 허용한 HTML만 남기고 화면에서도 DOMPurify로 정제한다. API는 `/api/voe` 아래에 있으며 Node 서버가 Python 저장 모듈을 호출한다.

## 테이블 준비

기존 MySQL/MariaDB 접속 파일 `DB_INFO_PATH`를 사용한다. 미설정 시 `/appdata/l0_spider/db_info.pkl`을 읽는다. Python 환경에 기존 서비스와 동일하게 `pymysql`이 필요하다. 접속 파일 내용이나 비밀번호를 출력하지 않는다.

```bash
# SQL 미리보기: DB에 연결하지 않음
python3 scripts/create_voe_tables.py

# 실제 생성: 한 번 실행하면 필요한 테이블 2개 생성
python3 scripts/create_voe_tables.py --apply
```

생성에는 `CREATE`/`REFERENCES` 권한이 필요하다. 기존 테이블은 삭제하거나 덮어쓰지 않는다. MySQL DDL은 자동 커밋되므로 실패 시 일부 테이블이 남을 수 있으며 원인을 해결한 뒤 재실행할 수 있다. 애플리케이션은 `SELECT`/`INSERT`/`UPDATE` 권한을 사용하며 자동으로 테이블을 만들지 않는다.

게시글 작성·수정 시 카테고리(`L0 SPIDER`, `L1 SPIDER`, `L3 SPIDER`, `Defect SPIDER`, `기타`)를 선택하며 기본값은 `기타`다. 목록과 상세 화면에 카테고리를 표시한다. 상태(답변 대기·답변 중·답변 완료) 필터는 유지하며, 검색·구분·라인·태그 및 라인 환경설정은 사용하지 않는다. 작성자·등록일·조회수 등 기본 정보는 유지한다.

카테고리는 JSON 문서와 목록 요약의 `category`에 저장한다. 작성·수정 API는 위 다섯 값만 허용한다. `category`를 생략한 작성 요청은 `기타`로 저장하고, 생략한 수정 요청은 기존 카테고리를 유지한다. 카테고리가 없거나 예전 분류값이 남아 있는 글은 조회 시 `기타`로 반환하며 다음 저장 시 정규화한다.

검색용 본문 복사본(`searchText`)과 라인·태그 등 제거한 분류 정보는 새 게시글에 저장하지 않는다. 이전 형식의 글도 읽기·수정할 수 있으며, 제거한 항목은 API 응답에서 제외하고 해당 글을 다음에 저장할 때 JSON 문서와 요약에서 정리한다. 일괄 데이터 수정이나 DB 테이블 변경은 필요하지 않다.

질문/답변 1건의 HTML 한도는 15 MiB, 질문과 답변을 포함한 저장 문서 한도는 48 MiB다. DB의 `max_allowed_packet` 설정이 더 작으면 이미지가 큰 글은 저장에 실패할 수 있다. 이력/알림은 최근 500건을 표시한다.

## 검증

```bash
python3 -B -m unittest discover -s scripts -p 'test_voe_board.py'
node --test server/voeBoard.test.mjs server/voeMail.test.mjs
```

Python 검증은 메모리 SQLite로 저장 흐름·권한·알림·복구·HTML 정제를 검증하며 운영 DB에 접근하지 않는다. 실제 MySQL DDL, 잠금 동작, SSO와 운영 DB 연결은 배포 환경에서 별도 확인이 필요하다.
