# VOE 게시판

메인 Apps의 기존 FDC Hard Limit 추천 자리를 `VOE 게시판`으로 교체한다. 카드 설명과 게시판 헤더 아래 문구는 `원하는 기능을 요청하거나 문의 사항을 등록합니다`이다. 경로는 `/voe`이며 기존 `/hard-limit` 접근은 `/voe`로 이동한다.

Quality-Hub 로컬 저장소의 `prototype/src/qna/QnaApp.jsx`, 서식 편집기와 CSS를 기준으로 목록/상세/작성 화면을 이식했다. 상태 필터, 표·이미지·글씨 크기 편집, 질문/답변 수정, 최종 답변, 알림, 삭제 복구, 변경 이력을 제공한다. 알림은 게시판 내부 알림이다. 외부 메일 발송은 연결하지 않는다.

## 권한과 저장

기존 Spider SSO와 접근 권한을 사용한다. 작성자는 자신의 질문/답변을 수정할 수 있으며 답변이 없는 질문만 삭제할 수 있다. 마스터는 모든 글 관리, 상태 변경, 최종 답변 지정, 삭제 복구와 변경 이력 조회가 가능하다. 클라이언트가 보낸 사용자 ID·권한을 신뢰하지 않는다. 개발 서버에서도 실제 쓰기에 SSO가 필요하다.

- `spider_voe_posts`: 질문, 답변, 서식/본문 이미지, 삭제 상태를 JSON 문서로 저장. 목록용 요약은 같은 행에 따로 저장하여 이미지 본문을 목록에 보내지 않는다.
- `spider_voe_events`: 변경 이력과 질문 작성자에게 보내는 답변/상태 알림, 읽음 상태를 함께 저장. 별도 사용자·첨부·알림 테이블은 만들지 않는다.

게시글 행을 `FOR UPDATE`로 잠근 뒤 변경 내용과 이력을 같은 트랜잭션으로 저장한다. 본문은 서버에서 허용한 HTML만 남기고 화면에서도 DOMPurify로 정제한다. API는 `/api/voe` 아래에 있으며 Node 서버가 Python 저장 모듈을 호출한다.

## 테이블 준비

기존 MySQL/MariaDB 접속 파일 `DB_INFO_PATH`를 사용한다. 미설정 시 `/appdata/l0_spider/db_info.pkl`을 읽는다. Python 환경에 기존 서비스와 동일하게 `pymysql`이 필요하다. 접속 파일 내용이나 비밀번호를 출력하지 않는다.

```bash
# SQL 미리보기: DB에 연결하지 않음
python3 scripts/create_voe_tables.py

# 실제 생성: 한 번 실행하면 필요한 테이블 2개 생성
python3 scripts/create_voe_tables.py --apply
```

생성에는 `CREATE`/`REFERENCES` 권한이 필요하다. 기존 테이블은 삭제하거나 덮어쓰지 않는다. MySQL DDL은 자동 커밋되므로 실패 시 일부 테이블이 남을 수 있으며 원인을 해결한 뒤 재실행할 수 있다. 애플리케이션은 `SELECT`/`INSERT`/`UPDATE` 권한을 사용하며 자동으로 테이블을 만들지 않는다.

게시글 분류는 상태(답변 대기·답변 중·답변 완료)만 사용한다. 작성 시 제목과 본문만 입력하며, 검색·구분·라인·태그 및 라인 환경설정은 사용하지 않는다. 작성자·등록일·조회수 등 기본 정보는 유지한다.

검색용 본문 복사본(`searchText`)과 분류 정보는 새 게시글에 저장하지 않는다. 이전 형식의 글도 읽기·수정할 수 있으며, 제거한 항목은 API 응답에서 제외하고 해당 글을 다음에 저장할 때 JSON 문서와 요약에서 정리한다. 일괄 데이터 수정이나 DB 테이블 변경은 필요하지 않다.

질문/답변 1건의 HTML 한도는 15 MiB, 질문과 답변을 포함한 저장 문서 한도는 48 MiB다. DB의 `max_allowed_packet` 설정이 더 작으면 이미지가 큰 글은 저장에 실패할 수 있다. 이력/알림은 최근 500건을 표시한다.

## 검증

```bash
python3 -B -m unittest discover -s scripts -p 'test_voe_board.py'
node --test server/voeBoard.test.mjs
```

Python 검증은 메모리 SQLite로 저장 흐름·권한·알림·복구·HTML 정제를 검증하며 운영 DB에 접근하지 않는다. 실제 MySQL DDL, 잠금 동작, SSO와 운영 DB 연결은 배포 환경에서 별도 확인이 필요하다.
